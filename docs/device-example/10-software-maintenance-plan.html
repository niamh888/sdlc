1. Purpose

This SOP defines how SentinelFlow 500 monitors feedback on released software, evaluates and implements changes, and re-applies development activities and, where necessary, re-classifies affected software items, per Clause 6.

2. Scope

Applies to all released versions of SentinelFlow 500's control software (Class C — see SOP-01 §7.3). Covers Clause 6 in full — every sub-clause applies to all three safety classes; Amendment 1's move of §6.2.3 from Class B/C to all classes made Clause 6 uniformly all-classes.

3. Responsibilities

RoleResponsibility under this SOP
Software Development LeadMonitors and evaluates feedback; analyses change requests for effect on the organisation, software, and interfacing systems
Risk ManagerEvaluates every problem report's effect on safety; re-evaluates classification if scope changes
QA/RAApproves change requests; confirms users and regulators are informed as required

4. Definitions & Abbreviations

TermMeaning
FeedbackPost-market information about released software — complaints, field reports, vigilance reports
Change requestA proposed modification to released software, evaluated before implementation

5. References

  • IEC 62304:2006+AMD1:2015, Clause 6
  • SOP-13 — Software Problem Resolution Process: every problem identified through maintenance feedback is managed through this process
  • SOP-01 — General Requirements & Classification: re-applied if a change materially expands intended use or introduces significant new functionality
